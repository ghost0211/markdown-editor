# XMD v1：Markdown 单文件资源包

XMD 是本项目定义的可移植文档容器，扩展名为 `.xmd`。它不是把 Markdown 改名，也不是把图片继续放在文档旁边：**正文和引用资源的实际字节都保存在同一个 ZIP 文件内**。

- 容器：标准 ZIP / DEFLATE。
- 应用约定的 MIME：`application/vnd.xmd+zip`（尚非注册标准）；通用传输也可使用 `application/zip`。
- 文本编码：UTF-8。
- 格式版本：1。
- 当前实现范围：**导出、打开、编辑及原格式保存**。Windows 安装包注册 `.xmd` 文件关联；请使用包含此功能的新版，旧版安装包不会显示该格式。

## 使用方法

1. 在编辑器中打开或编辑 Markdown。
2. 点击顶部「导出」→「导出 XMD」。
3. 选择保存位置，即得到一个 `.xmd` 文件；Web 开发模式会下载同样的文件。

桌面版会相对于**当前 Markdown 源文件**所在目录定位图片和本地附件，而不是相对于导出目标目录。未保存文档可以直接导出已粘贴的 `data:` 图片；使用相对本地路径时需要先保存文档。若通过拖入 Markdown 的方式打开，WebView 无法获得源目录，也需要先将文档保存到正确位置。

也可以直接在新版工具中打开 XMD，或将 XMD 拖入窗口。编辑器会安全校验清单、资源路径、大小与完整性，把包内图片和附件载入文档，而不是把 ZIP 当作纯文本打开。编辑后直接保存会重新打包回 `.xmd`；关联、最近文件、外部变更检查与自动保存沿用普通文档行为。

编辑器内部用内嵌数据表示包内资源，不需要将资源解压到磁盘。图片在编辑区折叠为简短名称，保存时恢复为包内资源。正文链接的附件可在预览中点击下载，始终以普通数据文件处理，不执行其中的 HTML 或 SVG。

仍可用 ZIP 工具通用解压 XMD，打开解压后的 `document.md`；请保留同级 `assets/` 目录，不要只拿走正文。

## 包内结构

```text
example.xmd                  # ZIP 容器
├── manifest.json            # 版本、入口、标题及资源清单
├── document.md              # Markdown 正文，资源引用已改成包内相对路径
└── assets/
    ├── 0001.png             # 图片的原始二进制内容
    ├── 0002.svg
    └── 0003.pdf             # 正文链接到的本地附件
```

不使用源文件名来创建 ZIP 路径，因此不同目录中的同名图片不会相互覆盖，也不会生成带盘符、绝对路径或 `../` 的归档条目。重复引用到同一解析地址的资源只写入一次；不同地址但内容相同的资源不做内容哈希去重。

### manifest.json

```json
{
  "format": "xmd",
  "version": 1,
  "entry": "document.md",
  "title": "示例.md",
  "resources": [
    {
      "path": "assets/0001.png",
      "mediaType": "image/png",
      "size": 12345
    }
  ]
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `format` | 固定为 `xmd` |
| `version` | 整数版本号；不兼容的变更需要新版本 |
| `entry` | v1 固定为 `document.md` |
| `title` | 导出时的文档标题 |
| `resources` | 本次实际打包的资源列表；无资源时为空数组 |
| `resources[].path` | 包内相对路径 |
| `resources[].mediaType` | 不含参数的 MIME 类型；未知附件使用 `application/octet-stream` |
| `resources[].size` | 原始资源的字节长度，而非压缩后大小 |

清单不记录源文件的绝对路径、下载 URL、认证信息或本机目录。注意：正文中未处理的普通链接、代码示例和 Front Matter 是原始内容，仍可能包含这些信息，分享前请自行检查。

## 资源识别规则

### 会打包

- 行内 Markdown 图片：`![说明](./images/example.png)`。
- 引用式、折叠式、快捷引用式图片，及其实际使用的定义。
- 本地相对路径、绝对路径、`file://` 图片（不支持 UNC 网络共享或带远程主机的 `file://host`）。
- HTTP / HTTPS 图片：下载成功后存入包内，正文不再依赖原图片服务器。`//cdn.example/image.png` 形式按 HTTPS 下载，绝不会当作 Windows 共享目录读取。
- 粘贴产生的 `data:image/...` 图片，以及当前会话中仍有效的 `blob:` 图片。
- 原生 HTML 的 `<img src>`、`<img srcset>` 和 `<picture>` 图片候选资源。HTML 原文不会被执行。
- Markdown 超链接指向的本地附件，如 `[附件](./report.pdf)`。页内锚点会保留；本地附件里的嵌套依赖不会递归打包。

空格、中文、百分号编码、Markdown 转义、括号嵌套、地址标题、引用定义共用以及图片片段标识（如 SVG 的 `#fragment`）都会按实际语法处理。本地文件名中的 `#`、`?` 请分别写成 `%23`、`%3F`（Markdown 的 `\#` 转义不改变 URL 锚点语义）。字面 `%` 可使用 `%25`，非法百分号转义也会按字面百分号处理。

### 不会打包

- 普通 HTTP / HTTPS 超链接、邮件链接和页内锚点。
- 代码块、行内代码、数学公式、HTML 注释、YAML / TOML Front Matter 中的示例地址。
- 未被使用的引用定义。
- CSS 的 `url()`、HTML 脚本/样式/iframe、音视频依赖、SVG 内部的外链依赖以及链接文档中的递归资源。v1 并不是网站离线镜像工具。

除资源地址（HTML 情况下是相关属性）外，不重新排版正文；原有换行、标题、表格、代码块、Front Matter、KaTeX 和 Mermaid 源码都保留。仅导出 XMD 不会更改当前标签的正文、路径、标题、保存快照或未保存状态；直接打开 XMD 时会按普通文档创建/恢复标签。

## 失败策略、网络与限制

**不静默丢图。** 任何要打包的资源不存在、读取失败、下载失败、不是可识别的图片或超过限额，都会中止导出，并指出对应资源。构建全部完成后才写入目标文件，因此资源收集失败不会写入半成品。底层目标文件写入仍沿用现有文件写入机制，磁盘故障时不保证原子替换。

- 单资源上限：32 MiB。本地资源在 Rust 读取前检查大小，读取时再次限流；正文/本地资源读取和整包写入采用二进制 IPC，避免将大包转为 JSON 数字数组。
- Markdown 原文与去重后资源总量上限：128 MiB（不含 ZIP 头和清单开销）。
- 不同资源数量上限：2048。
- 网络请求超时：30 秒；桌面端连接超时 10 秒，最多 5 次重定向。
- 仅支持 HTTP / HTTPS 网络请求，不传送浏览器 Cookie、Authorization 或 Referer；不接受带用户名/密码的 URL。URL 查询参数属于用户给出的资源地址，会随请求发送。
- 桌面端通过独立原生命令下载，不放宽 WebView 的 CSP；服务器须提供 `image/*` Content-Type。浏览器模式受 CORS、混合内容与浏览器权限限制，不能直接读取本地相对路径附件。建议含本地资源的文档使用桌面版导出。
- 图片字节不转码、不重采样；本地类型依据扩展名、网络类型依据 Content-Type 判断，并非图片内容的安全认证。
- **只对可信文档执行导出并分享**：正文链接到的本地附件（包括绝对路径、`file://` 和目录外路径）会将实际文件内容写入包内，不只是保存链接；本版本不弹出逐文件授权清单，也不限制资源在源目录内。分享前务必检查正文引用及解压后的资源，防止敏感文件被一起带出。
- 导出会实际访问图片 URL，包括本机/内网 HTTP 服务；未做公网地址限制。不要对来源不明、含敏感内网操作 URL 的文档执行联网导出。网络失败会在首个失败处终止；大量缓慢但成功的资源可能耗时较长，本版本暂无整包取消按钮或总时限。
- 打开时校验清单与资源数量/大小、拒绝路径穿越、重复条目、未知版本、缺失资源、包外/远程资源引用。不会读取本机路径或发起资源网络请求，不执行包内脚本；内嵌 HTML 仍按原预览白名单处理。
- ZIP 只是容器，不是加密或安全沙箱。不要在不可信阅读器里执行包内 HTML、SVG 或脚本。

## 兼容性与扩展

### 文档主题与分页

编辑工具栏的 XMD 区提供「文档主题」和「分页符」。文档主题随文件保存，导出 Word、PDF 或 HTML 时优先使用。它复用现有的字体、字号、配色、封面、目录、页眉和页码设置。导出菜单里的全局主题仍可给其他文档使用，批量导出选择了命名主题时按该主题输出。

「分页符」在光标所在的顶层段落、列表、表格或代码块之前插入分页，可撤销。Word、PDF 与打印 HTML 会从此处换页，编辑和阅读预览显示分页位置。

两项设置使用正文中的 Markdown 注释，主题位于文档开头或 Front Matter 之后。分页使用独立一行的 `<!-- xmd:page-break -->`。容器仍为 v1，解包后的正文可以用普通 Markdown 阅读器阅读。

### 局部文字样式

选中同一行内的文字，点击编辑工具栏的「XMD 文字样式」，可设置字体、字号和文字颜色。将光标放在已经设置样式的文字中，可再次修改或移除。保存为 XMD 时，这些设置会随正文保存。

工具栏右侧的 XMD 区有「字体」「字号」「颜色」三个快捷入口，可以直接应用预设值或清除当前样式中的单项设置。完整样式弹窗支持自定义值，并使用所选文字预览效果。

使用 XMD 文字样式或内嵌附件后，保存和另存为默认选用 `.xmd`。已有 Markdown 文件会先打开转存对话框，原文件保留，首次转存完成后可以继续自动保存到 XMD。

样式写在 `document.md` 中，标记内仍可包含 Markdown 粗体、斜体等行内格式。下面的标记为加粗文字指定宋体、18 pt 和深红色。

```markdown
待复核 <xmd-style font="宋体" size="18" color="#b91c1c">**重要条款**</xmd-style>。
```

开始和结束标记写在同一行。三个属性均可省略，至少填写一个。字号单位为 pt，范围为 6–96，步长为 0.5 pt。颜色使用六位十六进制值。包内保存字体名称，字体由阅读设备提供，缺少该字体时由系统回退。应用的预览、HTML、PDF、Word 导出和复制富文本可呈现这些样式。普通 Markdown 阅读器仍能读取正文，其显示样式取决于阅读器。

其他 XMD 阅读器应先检查 `format` / `version`，只使用包内相对入口，拒绝不支持的版本与越界路径。新增向后兼容字段可以保留版本号；改变正文、入口或资源解释规则应提升版本。

本项目支持导出、直接打开和保存；不承诺与其他同名扩展或第三方应用兼容。
